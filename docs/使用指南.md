## 2. 环境准备

上游 README 指定 Python `3.11.10`、PyTorch `2.4.1`。仓库未提供依赖锁定文件，不能将下面的依赖列表视为经过验证的完整版本组合。

主训练流程还导入以下第三方包：

```text
torchvision
numpy
scipy
scikit-learn
Pillow
openpyxl
matplotlib
seaborn
```

`scikit-learn` 在代码中写作 `sklearn`，`Pillow` 写作 `PIL`；`argparse`、`collections` 等是 Python 标准库，无需单独安装。`torchvision` 需与所安装的 PyTorch 版本匹配。

当前代码直接使用 `.cuda()`，需要可用的 NVIDIA GPU 和支持 CUDA 的 PyTorch 环境。进入准备好的 Python 环境后，可以先检查：

```powershell
python --version
python -c "import torch; print('PyTorch:', torch.__version__); print('CUDA available:', torch.cuda.is_available())"
python -c "import torchvision, numpy, scipy, sklearn, PIL, openpyxl, matplotlib, seaborn; print('Imports OK')"
```

这些命令仅检查版本、CUDA 可用性和导入情况，不会启动训练；通过检查也不等于完整实验已通过验证。

## 3. 数据与清单

数据下载地址沿用 [上游提供的百度网盘链接](https://pan.baidu.com/s/1d505GjqsmHWlwFG5hb5c3Q?pwd=5m1l)，提取码为 `5m1l`。本次未验证网盘内容或下载可用性。仓库自身不包含数据和预训练权重。

所有运行命令的工作目录应是 `SDALR` 仓库根目录。默认数据根目录是 `./DATA`，实际读取的清单如下：

| 数据集 | 默认目录 | 必需的域清单 |
| --- | --- | --- |
| JNU | `DATA/JNU_1d_2048_2000/` | `600_label.txt`、`800_label.txt`、`1000_label.txt` |
| PU | `DATA/PU_1d_8c_2048/` | `N15_M01_F10_label.txt`、`N15_M07_F10_label.txt`、`N15_M07_F04_label.txt` |

代码按 `<域名称>_label.txt` 查找文件，只有一个通用的 `label.txt` 无法满足默认入口的读取要求。每份清单应只列出对应工况域的样本；不要把同一份总清单复制成多个域来替代划分。

每行是“样本路径 + 整数类别标签”，以空白分隔。下面仅演示格式，不代表下载数据中的实际文件名或类别映射：

```text
./DATA/JNU_1d_2048_2000/data/NO/sample_001.txt 0
./DATA/JNU_1d_2048_2000/data/OR/sample_002.txt 1
```

- 样本路径按原样打开；相对路径相对于运行命令的工作目录，不相对于清单文件所在目录。
- 清单中的路径不能包含空白字符，清单应非空且不含空行，因为当前解析器直接使用 `split()`。
- JNU 默认为 4 类，标签范围为 `0–3`；PU 默认为 8 类，标签范围为 `0–7`。各域应使用一致的类别映射。
- 一个样本 TXT 内保存由空白分隔的数值；同一批次的样本长度应一致。仓库默认数据集名称对应 2048 点样本。
- `--folder_root` 改变清单所在的根目录，但不会自动重写清单内的样本路径。

## 4. 单个迁移任务

先进入包含 `README.md` 和训练脚本的目录。仓库没有 `object/` 子目录，无需执行旧说明中的 `cd object/`。

域索引从 `0` 开始，日志中的 `B1`、`B2`、`B3` 则从 `1` 开始：

| 索引 | 日志名称 | JNU 工况 | PU 工况 |
| --- | --- | --- | --- |
| `0` | `B1` | `600` | `N15_M01_F10` |
| `1` | `B2` | `800` | `N15_M07_F10` |
| `2` | `B3` | `1000` | `N15_M07_F04` |

例如 JNU 的 `600 → 800`，在 PowerShell 或 Bash 中依次运行：

```powershell
python src_pretrain_RES_JNU.py --s 0 --t 1
python tar_adaptation_RES_JNU.py --s 0 --t 1
```

例如 PU 的 `N15_M01_F10 → N15_M07_F10`：

```powershell
python src_pretrain_RES_PU.py --s 0 --t 1
python tar_adaptation_RES_PU.py --s 0 --t 1
```

第一条命令训练源域模型，并对指定目标域做迁移前评估；确认正常结束且已生成权重后，再执行第二条目标域适应命令。源域预训练仍需要目标域清单和数据来完成这一步评估。

以上命令只选择迁移方向，其他参数沿用各 Python 入口的默认值。环境准备完成后可用 `python tar_adaptation_RES_JNU.py --help` 查看参数；脚本会先导入依赖，缺包时 `--help` 也可能报错。

## 5. 批量实验与参数

批量脚本会使用多个源域，因此应先完成所选数据集全部源域的预训练。以 JNU 为例，在 Bash 中运行：

```bash
python src_pretrain_RES_JNU.py
bash choose_s_t_JNU.sh
```

PU 对应 `src_pretrain_RES_PU.py` 和 `choose_s_t_PU.sh`。`.sh` 使用 Bash 关联数组及 `awk`、`seq` 等命令，需要 Bash 4+；Windows 下可使用具备这些工具的 Git Bash 或 WSL，并确认其中的 `python` 能访问已准备的依赖、CUDA 和数据路径。

| 参数 | 当前实现中的含义 |
| --- | --- |
| `--s`、`--t` | 源域、目标域索引；默认 `-1` 会遍历对应域，适应阶段跳过源域与目标域相同的组合 |
| `--gpu_id` | 可见 GPU 编号，默认 `0` |
| `--seed` | 随机种子，默认 `2024` |
| `--worker` | 数据加载进程数，默认 `0` |
| `--batch_size` | 批次大小，默认 `64` |
| `--max_epoch` | 源域默认 `10`，目标域默认 `20` |
| `--lr` | 源域默认 `0.007`，目标域默认 `0.0005` |
| `--threshold` | 目标域到原型的距离阈值，默认 `0.4`；距离超过阈值会被排除，数值越小筛选越严格 |
| `--num` | 为 `-1` 时使用全部清单样本，否则抽样总量为 `num × class_num`；当前实现没有保证每类恰好抽到 `num` 个样本 |
| `--output` | 输出根目录，默认 `weight`；目标域也从该目录查找源域权重 |

JNU Python 目标域入口默认 `--num=-1`，但 `choose_s_t_JNU.sh` 设置了 `50 20 10 5` 的扫描。PU Python 目标域入口默认 `--num=2000`。使用有限样本数时，清单总样本数需满足代码所要求的抽样总量。

批量脚本的参数网格写在 `.sh` 内，和直接调用 Python 的默认参数不完全相同。判断任务是否成功应检查实际错误和日志；脚本末尾的 `All tests completed successfully.` 是固定输出。

## 6. 输出位置

默认根目录为 `weight/`，JNU 使用 `NEW_JNU`，PU 使用 `NEW_PU`。以 JNU 为例：

```text
weight/NEW_JNU/
├── Source-源域/
│   └── log&pt/
│       └── (B1)600/
│           ├── source_1.pt
│           ├── source_2.pt
│           ├── source_C.pt
│           └── log_时间戳.txt
├── Target-目标域/
│   └── log&pt/
│       └── (B1)600→(B2)800/
└── Picture-特征图/
```

上图是默认带瓶颈层时的部分输出结构。汇总 Excel 位于 `Source-源域/`、`Target-目标域/`，目标域权重与日志位于具体迁移任务的 `log&pt/` 子目录。图像目录按运行时间等进一步划分。

源域与目标域需使用匹配的模型参数和权重位置。如果调整 `--output` 或 `--username`，两阶段应保持一致。相同目录中的模型文件名固定，重新运行可能覆盖已有权重；需要保留独立实验时，为两阶段使用同一个新的 `--output` 目录。

## 7. 当前实现中需要留意的行为

以下内容是代码阅读记录，本次文档整理未修改这些行为：

- **分类损失权重**：两个主目标域入口将 `cls_par` 连乘两次，实际系数为其平方。默认值 `1` 时与乘一次相同，其他取值需按实际实现理解。
- **Dropout 参数**：`tools.read_model()` 创建 `ResNet18_1D` 时没有传入 `args.dropout`，当前使用模型构造函数的默认值 `0.1`。
- **源域标签平滑**：主源域交叉熵没有启用标签平滑；CutMix 分支和目标域伪标签损失使用了 `args.smooth`。仅修改源域命令行的 `--smooth`，在默认 `--mix=0` 时不会改变主分类损失。
- **目标域评估口径**：两个主目标域入口以 `separate=False` 和三个比例 `1` 创建 `train/val/test`，对应同一批抽取的目标样本，并按带真实标签的 `val` 准确率保存最佳模型。因此这里的 `test` 不是独立留出的目标测试集；记录结果时需说明这一实现口径。
